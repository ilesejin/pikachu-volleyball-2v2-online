# 피카츄 배구 2대2 온라인

[English](README.md) · [Firebase 및 배포 설정](ONLINE_SETUP.md)

현재 오프라인 2대2 게임을 WebRTC 방에서 플레이합니다. 브라우저 4개에서 각 1명씩 플레이하거나, 브라우저 2개에서 각 2명씩 플레이할 수 있습니다. 영어, 한국어, 중국어 번체 화면을 지원합니다.

기본값은 모든 브라우저가 기존 물리 엔진과 AI를 실행하는 록스텝 방식입니다. 브라우저 4개는 기본적으로 6개의 WebRTC 연결을 맺고 각자 입력을 나머지 3개 브라우저에 직접 보냅니다. 방장 중심의 3개 연결 방식도 선택할 수 있으며 이 방식에서는 방장이 입력을 모아 전달합니다. 모든 브라우저는 같은 입력과 같은 난수 시퀀스로 같은 프레임을 계산합니다. 설정 → 코트 / 서브에서 방장만 물리를 실행하고 게스트는 스냅샷을 표시하는 방식도 선택할 수 있습니다. 경기 중 전환하면 확인 후 같은 선수 구성으로 재시작합니다. Firebase 익명 인증은 참가자를 구분합니다. Firestore는 방 검색과 방장 연결을 위한 임시 시그널링에만 사용하며, 대기실 상태와 경기 중 입력·상태는 WebRTC로 전송합니다. 게스트 간 연결 설정도 방장을 통해 WebRTC로 전달합니다.

프로토콜 v5에서는 대기실 조작과 빠른 대전 대기 중 Firestore를 반복해서 읽거나 쓰지 않습니다. 연결 후 임시 시그널링을 삭제하고, 경기 시작 시 방 검색 항목을 삭제합니다. 대기실로 돌아오면 같은 방 코드를 다시 열어 참가할 수 있습니다. 프런트엔드 배포 전에 새 보안 규칙과 빠른 대전 서버(`/v2/match`)를 먼저 배포하세요. 이전 v4 대기실은 지원을 종료했습니다. `/rooms` 접근은 차단되며 `/v1/match`는 새로고침 안내와 HTTP 410을 반환합니다. 이전 클라이언트는 새로고침하고 새 방을 만들거나 참가해야 합니다. 자세한 순서는 [업그레이드 안내](ONLINE_SETUP.md#signaling-only-update-protocol-v5)를 참고하세요.

새 Firebase 프로젝트의 설정, 익명 로그인 활성화, 보안 규칙 적용은 [ONLINE_SETUP.md](ONLINE_SETUP.md)를 참고하세요. 설정 전에는 방을 만들 수 없습니다. 이전 Firebase 프로젝트의 설정을 새 게임에서 사용하지 않습니다.

`npm ci` 후 `npm start`를 실행하고 `/ko/`를 여세요. 방을 생성해 초대 링크를 공유하면 참가자가 빈 자리를 선택할 수 있습니다. 방장은 경기 시작·재시작·일시정지·대기실 복귀와 너비·서브·속도·승리 점수를 설정합니다. 싱글 매칭에서는 두 명 이상이 남아 있으면 나간 플레이어를 AI로 대체합니다. 경기 중 한 명만 남으면 중단하고 대기실로 돌아갑니다. 마지막 상대가 방장이었다면 남은 플레이어가 같은 방 코드의 방장이 되며 이름, 자리, 설정을 유지합니다. 여러 게스트가 남은 상태에서 방장이 나가면 방이 종료됩니다. 방장 이전 후에도 싱글 경기를 시작하려면 두 명 이상의 플레이어가 연결되어야 합니다. 듀오는 클라이언트 두 대가 연결되어야 시작할 수 있습니다. 경기 중 어느 한 듀오가 나가거나 연결이 끊기면 경기를 중단하고 남은 듀오는 대기실로 돌아갑니다. 방장이 나간 경우 남은 듀오가 같은 방 코드의 방장이 되며 이름, 팀 위치, 설정을 유지합니다.

기본 너비는 한쪽당 340입니다. 고정 시작 위치는 왼쪽부터 P1–P2–P3–P4이고 오른쪽은 P4가 먼저 서브합니다. 서브는 선수 교대, 공 위치 교대(기본값), 완전 고정 중 선택합니다. 같은 팀 선수는 서로 충돌하지 않으며 AI는 앞·뒤 구역을 담당합니다. 2대2 AI는 실제 충돌 규칙으로 공격 궤적을 예측하고 상대 두 명의 위치를 고려합니다. 안전한 공격이 있으면 네트나 자기 코트로 향하는 공격을 피하고, 낮은 위치에서 위험한 스매시 대신 위로 공을 올립니다. 기존 물리 및 충돌 특성은 유지합니다.

기본 조작은 로컬 1명일 때 방향키/Enter와 R/D/F/G/V/Z를 함께 사용할 수 있고, 2명일 때 첫 번째 R/D/F/G/V/Z와 두 번째 방향키/Enter입니다. 조작 설정에서 기존 선수별 키 배치를 선택할 수도 있습니다. 자세한 키 표와 구조 및 검증 방법은 [영문 README](README.md)를 참고하세요.

두 방식 모두 입력 전달에 인터넷 지연이 반영됩니다. 록스텝에서는 누락된 입력을 예측하지 않으며 느리거나 백그라운드에 있는 브라우저를 기다리므로 경기가 잠시 멈출 수 있습니다. 입력은 최대 3프레임까지 미리 모읍니다. 싱글 매칭에서 두 명 이상이 남았을 때 게스트가 나가면 모두 같은 프레임부터 해당 선수를 AI로 전환합니다. 듀오는 경기 중 방장 이전 대신 경기를 중단한 뒤 남은 듀오가 대기실 방장을 맡습니다. 게스트 예측은 구현하지 않았습니다. 일부 네트워크는 TURN 서버가 필요합니다.

검증: `npm test`, 개발 빌드 후 `npm run test:browser`, `npm run build`. 배포 전에는 반드시 Git 원격 주소를 확인하세요. 폴더 이름과 기존 원격 저장소 이름이 다릅니다.

## 빠른 대전

같은 새 Firebase 프로젝트를 사용하도록 형제 폴더의 `pikachu-volleyball-2v2-online-quick-match-server-main` 서버를 설정하세요. `src/resources/js/online_2v2/quick_match_config.js`의 `quickMatchServerURL`에 서버 HTTPS 주소를 입력하면 빠른 대전 버튼이 활성화됩니다. 자세한 설정은 서버 README를 참고하세요.

인원 배치를 선택한 뒤 **빠른 대전**을 누르세요. 지역 선택 없이 배치별 공용 대기열을 사용하며 국가나 IP를 제한하지 않습니다. 첫 브라우저가 방장이 되고, 다음 참가자들은 대기실에 들어와 빈 자리 또는 팀을 직접 선택합니다. 빈 자리는 항상 AI가 담당합니다. 싱글은 두 명 이상의 사람이 연결되어 자리를 선택하면 시작할 수 있으며, 듀오는 두 클라이언트가 필요합니다. 경기 시작 후에는 새 빠른 대전 참가자를 받지 않습니다. 빠른 대전 방은 기본 공개, 친구 방은 기본 비공개입니다. 방장은 대기실 또는 설정 메뉴의 **방 공개 설정**을 경기 재시작 없이 변경할 수 있습니다. 공개 대기실은 자동으로 빠른 대전에 등록됩니다. 공개·비공개 모두 경기가 끝나면 게임 종료 애니메이션 후 같은 대기실로 돌아옵니다. 공개 여부는 유지되며 공개 방만 다시 검색할 수 있습니다. 경기 중이거나 비공개인 방은 검색되지 않지만 비공개 방에도 초대 링크로 참가할 수 있습니다. 프런트엔드보다 빠른 대전 서버를 먼저 갱신하세요. 초대 링크 방식도 계속 사용할 수 있습니다.

## 기존 P2P 화면과 채팅

기존 P2P의 첫 화면, 메뉴 바, 설정 하위 메뉴, 화면 테마와 채팅 입력 바를 사용합니다. **친구들과 함께 → 방 만들기**로 방을 만들거나 빠른 대전을 선택하세요. 방장은 **게임 → 시작 / 재시작**으로 경기를 시작합니다.

**설정** 메뉴에서 그래픽, 배경음, 효과음, 속도, 승리 점수를 선택합니다. **코트 / 서브**에서 너비, 서브 방식과 물리 동기화 방식(기본값: 모든 브라우저)을 바꿉니다. 경기 설정은 방장만 변경합니다. 경기 중 속도와 연습모드는 확인 후 즉시 적용되며 점수, 현재 랠리, 서브 순서와 일시정지 상태를 유지합니다. 코트 너비, 서브 방식, 승리 점수 또는 물리 동기화 방식을 바꾸면 같은 선수 구성으로 재시작합니다. 그래픽·소리·테마·키 배치는 각 브라우저에만 적용됩니다.

**Space** 또는 **채팅** 버튼으로 메시지를 입력하고 **Enter**로 모두에게 보냅니다. **Escape**로 입력을 닫으며 **채팅 끄기**는 내 브라우저에서만 채팅을 끕니다. 대기실과 경기 중 모두 사용할 수 있고, 로컬 2명은 각자 이름을 정하고 채팅 이름에서 화자를 선택합니다. 채팅은 방장을 통해 WebRTC로 전달되며 Firestore에 저장되지 않습니다. 브라우저당 1명인 모드에서는 코트를 P1–P2–P3–P4 순서의 네 영역으로 나누어 자기 자리의 영역 안에 채팅을 무작위로 표시합니다. 로컬 2명씩 플레이하는 모드의 배치는 기존과 같습니다.

## 자리 선택, 선수 이름과 연습모드

초대와 빠른 대전 모두 대기실에 자리 미선택 상태로 입장합니다. 1명은 빈 자리 하나를, 로컬 2명은 빈 팀 전체(P1+P2 또는 P3+P4)를 선택합니다. 선택을 취소하거나 다른 빈 자리로 바꿀 수 있습니다. 방장은 **자리 무작위 배정**으로 현재 대기실의 모든 참가자를 다시 배정할 수 있습니다. 1명씩 참가하면 P1~P4 중 무작위로, 로컬 2명은 P1+P2 또는 P3+P4 팀 단위로 배정하며 두 선수의 순서와 이름을 유지합니다. 남는 자리는 AI가 사용할 수 있습니다. 참가한 사람 모두가 자리를 고르고 연결되어야 방장이 시작할 수 있습니다. 남는 자리는 AI로 채울 수 있습니다.

각 브라우저는 대기실에서 자기 선수들의 이름을 바꿀 수 있습니다. 로컬 2명의 이름은 팀을 바꿔도 유지되며 채팅의 이름 선택에서 화자를 고릅니다. 채팅은 기존처럼 같은 편의 무작위 좌표에 나타나고, 같은 선수의 이전 메시지를 교체합니다. 모두에게 같은 좌표가 보이며 경기 물리 난수와 분리되어 있습니다.

설정 메뉴에 연습모드와 기본 설정 복원을 추가했습니다. 연습모드는 기존 오프라인 동작처럼 점수판을 숨기고 승리점수에 의한 종료를 막습니다. 기본 설정 복원은 이름과 자리를 유지합니다. 대화상자가 없을 때 Escape로 메뉴 바를 숨기거나 표시합니다.

이번 대기실은 `pikavolley-2v2-v5` 형식입니다. 배포 시 프런트엔드, 빠른 대전 서버와 `firestore.2v2.rules`를 함께 갱신하고 새 방을 만드세요.

같은 브라우저 프로필의 다른 탭이나 창에서도 각각 독립적으로 참가할 수 있습니다. 탭마다 메모리에 별도의 익명 인증 세션을 사용합니다. 새로고침하면 경기에서 나가고 새 참가자 세션이 생성됩니다. 같은 탭에서 두 번 참가하는 경우만 제한합니다.

## 연결 방식

설정 → 코트 / 서브에서 방장은 전체 연결 6개(기본값) 또는 방장 중심 연결 3개를 선택할 수 있습니다. 로컬 2명씩 참가하는 브라우저 2개는 항상 연결 1개를 사용합니다. 4명 미만이면 실제 참가한 브라우저에 필요한 연결만 생성합니다. 모든 연결이 준비되어야 시작할 수 있습니다. 경기 중 연결 방식을 바꾸면 이름과 자리를 유지한 채 대기실로 돌아가 연결을 다시 만듭니다.

전체 연결에서는 평소 입력을 직접 교환하고, 일시정지·속도/연습모드 변경·AI 전환 때만 방장의 전체 상태 및 난수 체크포인트로 동기화합니다. 이때 위치가 조금 보정될 수 있습니다. 게스트끼리의 연결만 실패하면 모두 대기실로 돌아갑니다. 방장은 연결 다시 시도 버튼을 누르거나 3개 연결로 바꿀 수 있습니다. 실제 게스트가 나가면 AI로 전환되며, 한 명만 남으면 경기를 중단하고 대기실로 돌아갑니다. 마지막 상대가 방장이면 남은 플레이어가 방장을 맡고, 여러 게스트가 남았을 때 방장이 나가면 방이 닫힙니다.

## 오프라인 엔진 자동 동기화

형제 폴더 `../pikachu-volleyball-2v2`를 공유 엔진의 원본으로 사용합니다. 온라인 프로젝트에서 `npm start`, `npm run build`(배포 포함), `npm test`를 실행하면 자동으로 복사본을 동기화합니다. 개발 서버 실행 중에도 오프라인 소스 변경을 감지해 다시 빌드합니다.

`npm run sync:offline`은 즉시 동기화하고, `npm run check:offline`은 파일을 바꾸지 않고 차이가 있으면 실패합니다. 다른 위치의 원본을 쓰려면 `PIKA_OFFLINE_ROOT`에 오프라인 프로젝트 경로를 지정하세요. 새로 import한 공유 모듈도 자동 포함됩니다. 공유 엔진은 오프라인 프로젝트에서 수정하세요. 온라인의 복사본 수정은 다음 동기화 때 원본으로 덮어씁니다.

복사된 엔진과 `offline-engine.manifest.json`을 함께 커밋하세요. 기본 형제 폴더가 없으면 해시를 검증한 저장소 내 스냅샷으로 독립 빌드합니다. 직접 지정한 원본 경로가 없거나 복사본이 변조되어 있으면 실패합니다. 배포된 게임에는 프런트엔드를 다시 빌드하고 배포한 뒤 변경이 반영됩니다.

자동 브라우저 테스트는 항상 Chrome 소리를 음소거한 상태로 실행합니다.

빈 채팅이나 공백만 입력하고 Enter를 누르면 메시지를 보내지 않고 채팅 입력창을 닫습니다. 선수 위치 표시는 기본적으로 게임 시작! 문구와 함께 사라집니다. **설정 → 선수 위치 표시 → 항상 표시**로 계속 표시할 수 있으며, 선택은 이 브라우저에 저장되고 다른 선수나 경기 진행에 영향을 주지 않습니다. 구름은 설정한 코트 너비 전체를 이동합니다.

실제 게임 화면 템플릿은 `src/en/index.html`, `src/ko/index.html`, `src/zh/index.html`입니다. 빌드하면 각각 `/en/`, `/ko/`, `/zh/`로 제공되며 중복된 이전 템플릿은 삭제했습니다. 제작자 표기, 관련 버전·소스 코드 링크, 공개 날짜 표시 및 업데이트 기록은 오프라인 2대2 버전과 일치합니다.

기본 속도는 **빠르게(30 FPS)**입니다. 첫 번째 닉네임은 기존 P2P 버전과 같은 localStorage의 `myNickname` 키에, 두 번째 로컬 선수 이름은 `mySecondNickname` 키에 저장됩니다. 대기실에서 저장한 이름도 창을 닫았다가 다시 열면 복원됩니다. 방 참가 상태나 분리된 탭의 식별자는 복원하지 않습니다.

## 리플레이

**리플레이 저장**은 현재 방의 재대전·재시작을 포함한 전체 세션을 원본 P2P와 같은 `.txt` 파일로 저장합니다. 기존 `.pvreplay` 파일도 계속 열 수 있습니다. 저장 후에도 기록은 계속됩니다. **퇴장 시 자동 저장**은 기본으로 켜져 있으며 설정은 브라우저를 다시 열어도 유지되며, 창을 닫을 때의 다운로드는 브라우저에 따라 제한될 수 있습니다. 연결 종료 후에도 다른 방에 들어가기 전까지 마지막 기록을 직접 저장할 수 있습니다.

방장은 실제 시뮬레이션을 기록합니다. 게스트는 일시정지·경기 종료·대기실 상태에서 저장하면 별도의 WebRTC 채널로 방장의 전체 기록을 받습니다. 경기 중이거나 연결이 끊겼다면 보유한 로컬 기록을 저장하며, 이는 일부 기록으로 표시됩니다. 방장만 물리를 실행하는 모드의 게스트는 받은 화면 상태를 기록합니다. 게스트의 자동 저장은 로컬 기록을 사용합니다. Firestore 저장이나 추가 읽기·쓰기는 없습니다.

`/ko/replay/`에서 기존과 같은 재생·탐색·속도·채팅·이름·소리 설정을 사용할 수 있습니다. 영어와 중국어 번체도 지원하며, 기존 P2P 1대1 `.txt` 리플레이도 열 수 있습니다. 새 파일에는 IP 주소를 저장하지 않습니다. 대기 시간·네트워크 지연·실제 일시정지 시간은 재생 시간에서 제외됩니다. 엔진 버전이 다르면 정확하지 않은 재생 대신 오류를 표시하므로 장기 보관 시 해당 버전의 뷰어 빌드도 보관하세요. 파일과 전송 크기 제한은 128 MiB입니다. `npm run test:replay`는 음소거 상태로 브라우저 검증을 실행합니다.

키 뷰어는 기존 2P와 같은 방향키·Enter 패드 4개를 표시합니다. 다운로드는 원본 P2P의 FileSaver 방식을 사용하며, 사이트 자체 저장 창은 열지 않습니다. 브라우저의 다운로드 위치 확인 설정은 그대로 적용됩니다. 리플레이 재생기 링크는 원본처럼 소개와 리플레이 설명에 배치했습니다.

자동 저장 체크박스는 원본처럼 경기 전 설정 영역에, 리플레이 저장 버튼은 경기 화면 위 옵션 옆에 배치했습니다. 크롬의 파일 이름·위치 선택 창을 없애려면 `chrome://settings/downloads`에서 다운로드 전에 각 파일의 저장 위치 확인을 끄세요. 사이트에서 이 브라우저 설정을 강제로 바꾸지는 않습니다.

## 클라이언트 업데이트 확인

빌드할 때 생성되는 `version.json`으로 최신 배포 여부를 확인합니다. 방 생성·참가와 경기 시작·재시작 전에 확인하며, 새 버전이면 새로고침 안내를 표시합니다. 진행 중인 경기는 중단하지 않습니다. 참가자들의 빌드·네트워크 프로토콜·엔진 지문이 모두 일치해야 참가하고 경기를 시작할 수 있습니다. 새로고침은 방에서 나간 뒤 진행하며 저장된 이름과 로컬 설정은 유지합니다.

이번 기능이 없는 기존 탭은 한 번 직접 새로고침해야 합니다. `npm run deploy`로 `version.json`을 포함한 전체 프런트엔드를 배포하세요. 이 기능에는 서버 재배포나 Firestore 규칙 변경이 필요하지 않습니다.

## 핑과 연결 상태

대기실에서는 검은색 연결 상태 패널이 열리며, 강제 카운트다운은 없습니다. 경기 중에는 메뉴 아래의 간단한 핑 표시를 눌러 상세 정보를 열 수 있습니다. 처음 5회는 1초 간격으로, 이후에는 2초 간격으로 왕복 시간을 측정하고 최근 최대 10회의 평균·범위와 직접 연결/TURN/알 수 없음 상태를 표시합니다. 로컬 2명은 하나의 연결로 표시합니다.

메시 방식은 6개 연결을 공유해 표시하고, 스타 방식에서 직접 연결이 없는 경로는 방장 경유로 표시합니다. 방장 물리 방식에서 사용하지 않는 게스트 간 연결은 대표 핑 계산에서 제외합니다. 응답 없음이나 오래된 측정값을 0ms로 표시하지 않습니다.

핑은 실제 키 입력 지연과 다릅니다. 별도로 누락된 입력을 기다리는 상태를 관측하며, 일시정지와 정상적인 프레임 대기는 제외합니다. 측정은 물리·난수·리플레이 기록에 영향을 주지 않고 Firestore나 빠른 대전 서버 요청을 추가하지 않습니다.


록스텝 입력은 짧은 준비 및 시계 측정 절차 후 방장 기준의 공통 주기에 맞춰 수집합니다. 기존 피어 연결의 왕복 시간을 측정해 입력 선행 범위를 조정하며 최대 3프레임을 유지합니다. 한 브라우저가 먼저 입력을 수집해 대기열이 계속 깊어지는 현상을 줄이고, 타이머 지연 후에도 균형을 회복합니다. 일시정지 해제 및 경기 속도 변경 시에도 랠리를 재시작하지 않고 공통 주기를 다시 설정합니다. 관련 제어 메시지는 WebRTC만 사용하며 리플레이에 저장하지 않습니다. 물리와 실제로 기록되는 시뮬레이션 입력은 변경하지 않습니다. 네트워크 지터, 비대칭 경로 및 브라우저의 백그라운드 제한에 따른 지연은 발생할 수 있습니다.


사용하지 않는 구형 실시간 1대1 게임, 지역별 매칭, IP 차단, NAT 검사, 구형 설정 합의 UI 및 기록기, iframe 안내를 제거했습니다. 기존 1대1 리플레이는 원래 물리, 시드 기반 채팅 위치, 닉네임 및 파일에 기록된 부분 IP 표시를 그대로 지원합니다. `replay/legacy_chat.js`는 네트워크 전송이나 재기록 없이 기존 채팅을 표시합니다. 온라인 연결은 현재 2대2 코드만 담당하며, 폐기된 `/rooms`의 접근 차단 규칙은 유지합니다.


방 참가 시 조회 및 WebRTC 연결이 진행되는 동안 중앙에 연결 중 화면을 표시합니다. 빠른 대전 참가에도 적용되며, 성공하거나 실패하면 닫힙니다. 링크 또는 코드 복사에 성공하면 버튼 크기를 유지한 채 초록색 체크 애니메이션을 잠시 표시합니다. 복사 실패 시 기존 수동 복사 방식을 제공하며, 동작 줄이기 설정을 따릅니다.

방을 만들 때도 대기실 준비가 끝날 때까지 같은 진행 화면을 표시합니다. 초대 링크 입력란과 링크·코드 복사 버튼의 높이는 동일합니다.

## 방장 위임

대기실에서 방장은 연결된 참가자 옆의 **방장 위임** 버튼을 누를 수 있습니다. 모든 참가자의 연결이 완료되어야 하며 경기 중에는 사용할 수 없습니다. 기존 방장은 방에 남고, 방 코드·이름·자리·경기 설정·공개 여부·채팅·방장 리플레이 기록을 유지합니다. 연결은 새 방장을 기준으로 재구성되며 빠른 대전 공개 등록도 새 방장으로 이전됩니다.

프런트엔드를 배포하기 전에 갱신된 `firestore.2v2.rules`를 먼저 게시하세요. 동일한 방 검색 문서의 `hostId`만 트랜잭션으로 변경하며 기존 방장의 쓰기 권한은 사라집니다. 권한 변경에 실패하면 위임을 취소하고 기존 방장이 유지됩니다. [설정 안내](ONLINE_SETUP.md#manual-host-handoff)를 참고하세요.

## 플레이어 의상

메인 화면의 **의상** 버튼으로 방 생성·참가 또는 빠른 대전 전에 의상을 선택할 수 있습니다. 로컬 2명은 각각 선택하며 브라우저를 다시 열어도 저장됩니다. 대기실에서도 의상 버튼이나 자신이 배정된 피카츄 그림을 눌러 바꿀 수 있지만 경기 중에는 변경할 수 없습니다.

기본·모자·머리띠·스카프를 제공하며 중복 선택이 가능합니다. 원래 28개 애니메이션 프레임을 그대로 사용하고 의상만 별도 텍스처로 합성합니다. 의상 색을 유지하면서 선수 아래의 위치별 색상 표시로 구분합니다. 자리 변경·무작위 배정·방장 위임 시에도 선택이 유지됩니다. 빈 자리 AI는 기본 의상을 사용하고, 퇴장한 선수를 대신하는 AI는 해당 경기의 의상을 유지합니다.

새 리플레이에는 의상 정보가 포함되고 이전 파일은 기존 색상 그대로 재생됩니다. 오프라인 버전과 공유 물리 엔진은 변경하지 않았으며 의상 선택으로 Firestore 사용이 늘어나지 않습니다.


의상 선택창의 **머리**(없음·모자·머리띠)와 **목**(없음·스카프)을 각각 선택한 뒤 **적용**하면 함께 착용할 수 있습니다. 적용하지 않고 닫으면 변경을 취소합니다. 이전에 저장한 단일 의상 선택과 리플레이도 호환됩니다.

실제 그림 파일은 `src/resources/assets/images/costumes/`의 `cap.png`, `headband.png`, `scarf.png`입니다. 모두 피카츄 프레임 영역만 남긴 476 × 262 크기의 투명 PNG입니다. 위아래의 불필요한 여백을 제거하고 공통 Y 오프셋 266을 메타데이터에 저장하여 원본의 28개 프레임과 정확히 맞춥니다. 프레임 내부의 여백과 간격은 유지합니다. 이미지 편집기로 직접 수정할 수 있으며 자세한 프레임 정보와 편집 방법은 같은 폴더의 `README.md`와 `frames.json`에 있습니다. 그림은 로딩 시 한 번 합성해 재사용하며 빌드 시 파일 내용에 따른 URL을 생성합니다.
